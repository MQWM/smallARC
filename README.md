# SmallARC · 小小箭头辅助工具

Mac 桌面辅助窗口与 scrcpy 并排使用。通过一张完整截图识别网格箭头、计算全部消除顺序；手机接入后，用 ADB 按顺序执行整关。

## 启动

本项目仅在本机使用，通过 Python 直接运行源码。

当前仓库已经建立 `.venv` 并安装依赖。双击 `start.command`，或在当前目录执行：

```bash
.venv/bin/python app.py
```

首次安装或新电脑上，使用 Python 3.11 创建虚拟环境：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
```

锁定依赖在 macOS ARM64、Python 3.11.16 上验证；该组 NumPy 构建要求 macOS 14 或更高版本。工具依赖 `PySide6-Essentials`，不要同时安装多个提供 `cv2` 的 OpenCV 包。

## 连接安卓并自动点击

1. 手机开启 USB 调试，连接 Mac，在手机上授权。
2. 点击“刷新设备”，选择状态为 `device` 的手机。ADB 和 scrcpy 自动寻找 PATH 或 `/opt/homebrew/bin`。
3. 点击“启动投屏”，将 scrcpy 手机窗口和辅助窗口并排摆放。
4. 在游戏中进入关卡，调整到完整棋盘可见，保持游戏缩放与位置不变。
5. 点击“获取截图”，程序自动框选棋盘并显示黄色范围框；需要时可用“框选棋盘”手动调整。点击“识别关卡”。
6. 核对箭头及方向后，勾选“已逐条核对”，点击“执行整关 / 继续”；识别完成不会自动点击。
7. 手动操作游戏前先“停止”；改变棋盘后重新获取截图和识别。

桌面只提供整关执行：一张截图计算完整顺序；发现小豆豆时，执行前额外抓一帧测速。中途和继续时不抓图，进度表示已发送，不能作为实际过关证明。停止阻止后续点击，不能撤回已发指令；成功发送的步骤继续时不重复点击，导弹倒计时不会重置。桌面已移除导入截图，执行使用当前所选设备抓取的原图。

### 图上纠错

- 编辑箭头：在图上或列表选择箭头，再按“编辑箭头”；也可先按编辑，再在图上选择。
- 补画箭头：按“补画箭头”，依次点击尾部、拐点、头部；方向自动推断，也可通过方向按钮调整。
- 拖动控制点修改路径，滚轮缩放；右键或“撤销末点”退回一步。
- “设置点击点”后在箭头头部内点击，红圈表示手机点击位置。
- Enter 或“保存”提交并重新求解，Esc 或“取消”放弃；保存后需重新核对才能执行。
- 导弹和粗箭头保留其视觉占用，可调整点击点；修改这两类的完整路径需要重新识别。

日志最多保留 500 行，新日志自动滚动到底部。

### 自动下一关

胜利后按“自动下一关”。未勾选连续执行时，进入后仅更新截图，等待手动识别与核对。勾选“自动下一关、识别并连续执行”（默认关闭）后，点击“执行整关 / 继续”或在胜利页点击“自动下一关”启动连续流程：确认胜利页 → 点击一次下一关 → 每 5 秒检查进入 → 自动识别与求解 → 整关执行 → 再次下一关，直到停止或异常。

新关卡独立保存记录、清除旧进度和计时，不需要逐关手动勾选核对。识别报告问题、计划无解、执行前校验失败、导弹秒数缺失或时间不足时立即停止，不自动忽略问题。新关导弹仍从本关首次箭头点击开始计时，不沿用上一关的截止点。

等待期间可以“停止”；120 秒内未确认进入则停止并提示检查手机。不重复点击下一关。按钮与标题模板来自第 262 关胜利页，随截图宽度缩放；不同胜利页样式尚未适配时不会猜坐标点击。整关过程仍不抓图，只有启用此功能后的跨关等待会抓图。

### 倒计时子弹

灰色描边导弹不会被点击。首次点击后，倒计时内从末尾向头部燃烧，烧到头部才沿方向发射；燃烧过的格子在发射前仍然阻挡其他箭头。求解始终保留整条路径的占用。程序先清理它的直接和间接阻挡者，再等待倒计时结束与离场，最后执行后续箭头。执行仅按时间推定离场，不在中途截图。

识别后核对右上角倒计时，在辅助窗口确认“截图显示的秒数”。默认倒计时尚未启动：截图、识别和人工核对不消耗时间，程序从首次向游戏发送点击时开始计时，之后继续执行不会重置。如果抓图前已在游戏中点击过，请勾选“抓图时倒计时已经启动”，此时用截图剩余秒数扣除抓图后的时间。预计清障时间不足时停止。默认到时后等待 5 秒离场，此值尚需根据实机动画调整。

### 粗箭头

已支持第 202 关截图中带装饰的直线粗箭头。识别填充外轮廓，排除内部图案干扰；覆盖图以 `WIDE` 和格子边框标记其占用。求解按最大宽度保守覆盖整个直线身体与前进通道，该样本占 3 列，不能只清理中心线。点击一次，参与整关执行。

第 342 关中，红色粗箭头尾部与青色小箭头粘连，仅为皮肤视觉覆盖，小箭头仍可操作。识别先用红/金皮肤恢复宽箭头，再拆出有独立可见头部的彩色邻居，内部黑白装饰归入皮肤；识别和执行前校验使用同一分区。只在粗箭头尾部修剪没有真实皮肤支撑、又与可见普通箭身冲突的保守占用格，其余三列宽度碰撞保留，不添加视觉遮挡先后依赖。

原图及 125% 缩放下完整识别 121 支箭头；75% 下这对箭头可恢复，但另有细箭头路径失真，仍拒绝完整自动执行。不能从一张图还原完全不可见的箭头、隐藏拐点或未知叠层皮肤；当前不会任意补画隐藏路径。

初始规划请使用导弹尾部完整的截图。单张燃烧途中的图片无法还原此前已燃烧的隐形占用。

### 旋转黑瞳

已支持第 203 关的黑瞳入口：识别为可重复使用的消失入口，覆盖图标记 `EXIT`。箭头沿头部方向到达黑瞳后消失，因此只需清理入口之前的阻挡，不计算入口后方的箭头。黑瞳不加入点击顺序，也不会被删除。

黑瞳旋转纹理的截图对比仅保留在回归测试中。该关原始截图识别为 122 个箭头与 4 个黑瞳。

### 数字障碍、斜向箭头和闪电

第 205 关新增：数字方块 40、80，成功消除一支被点击的箭头后减 1，到零消失。程序识别方块位置和数字，先安排其他可消除箭头，满足计数门槛后才开放被方块阻挡的通道。核对覆盖图中的 `BLOCK` 数字；读数不确定时停止执行并重新抓图，不猜测门槛。

数字方块相关动作会在导弹清障优先级不变的前提下，排在当前可执行的无方块通道之后。达到某个计数门槛的点击发送完成后，至少等待 2 秒才使用该方块通道；已有后续安全动作消耗的时间计入等待，不为每支箭头重复追加 2 秒。等待可停止，继续不重复发送旧点击；导弹清障预算包含这些等待。执行记录用 `waiting_counter` 标出等待。整关仍不截图，缓冲是时间估计，不能检测此前的漏点或失败。

支持水平、垂直和 45 度网格斜线，碰撞包含斜段半格交点；非 45 度斜线使用真实像素折线和有宽度的发射通道。飞出角度未确认时同时检查头部分类方向和实际末段斜率。

闪电箭头标记为 `FLASH`。点击后可能自动消除其他可点击箭头。整关执行仍按原顺序继续，部分后续点击可能因目标已经消失而无效；需要更新计划时停止、重新获取截图和识别。

闪电额外消除不会使原计划中的数字障碍更晚解锁：在不漏点的前提下，已处理的不同箭头都已消失，实际消除数量不小于规划的保守计数。

预览绘制已改为将已执行箭头合并到一个掩膜中，一次处理图片；日志最多保留 500 行。识别、求解和启动导出在后台执行，减少执行后期界面卡顿。

### 有次数的转弯通道

第 316、317 关的蓝色 L/U 通道已支持，覆盖图用 `TURN 编号: 剩余次数` 标记。两个开口都能进入，按进入的一端沿通道转向，从另一端退出；撞到封闭侧面会被挡住。出口前方必须畅通，只有成功通过才扣通道次数，到零后通道消失，之后从这里经过的箭头恢复直行。

求解逐步模拟通道剩余次数与箭头占用，并在必要时回溯选择顺序。每次发送经过通道的点击后，等待至少 2 秒再发送下一步，让转弯和通道消失动画完成；这是时间缓冲，执行中仍不抓图核验。停止后继续会保留等待时间且不重发已发送的点击。

当前适配这些实拍中的蓝色 L/U 样式与普通箭头组合；通道与粗箭头、导弹、闪电或未确定发射角度的组合暂不自动执行。稀疏通道关卡的网格仅辅助定位，碰撞和执行前路径校验使用真实像素折线。

### 外围小豆豆的简单避让

第 332 关的黄色角色沿外围虚线矩形匀速绕圈，碰到箭头头部会让箭头退回。轨道上的沙漏、小心心及其他小型道具统一忽略，不按颜色或皮肤逐种识别；只定位小豆豆用于避让。该样式的棋盘框选固定在虚线轨道内，外围物体不参与箭头识别；覆盖图用 `ORBIT` 标出轨道和截图时的角色位置。

获取截图时若检测到小豆豆，约间隔 0.8 秒自动再抓一帧，按矩形轨道上的位移和实际时间间隔估算速度与方向，跨拐角也按轨道距离计算。第二帧用于识别和规划，测速自动填入“小豆豆速度”“移动方向”，仍可手动调整；无小豆豆时只抓一帧。测量失败会明确提示，手动模式保留面板参数供核对，自动连续执行则停止。

示意图中橙色空心圈及 `CAPTURE` 表示截图时的位置，青色圆点实时显示预测位置，带方向箭头的轨迹表示接下来 1 秒的移动。只更新少量图形项，不重复渲染整张棋盘。执行保持原顺序；若预测小豆豆会在未来窗口内经过当前箭头的出口附近，就等它通过后再点。避让窗口默认 3 秒，加入角色体积、半个箭身宽、0.5 秒抓图/命令余量，以及随截图年龄每秒增长 0.005 秒的速度误差余量。窗口需要覆盖箭头从点击到头部抵达轨道的时间，仍碰撞时可调大。

每帧时间取 ADB 抓图前后单调时钟的中点，测量成功后从第二帧时间开始推算位置，识别、核对和停止期间仍计入移动时间；继续执行沿用原截图时间，不把角色位置重置。自动下一关也会重新测速，更新本关速度和方向，保留手调避让窗口。执行中仍不抓图、不核验是否退回。预测窗口覆盖整圈或等一圈也找不到窗口时停止，提示调整参数或重新抓图。当前不自动执行小豆豆与倒计时子弹的组合。

118 像素/秒来自两帧测量的近似值，单位为手机原始截图坐标。绕圈时间根据当前轨道周长除以速度自动计算，地图大小变化不改变速度参数，3 秒窗口是假设值，没有标定箭头速度。此功能用于降低碰撞风险，不保证无碰撞，也没有测得实际失败概率。

### 成对传送门

第 409 关新增青蓝拱门、白色四角星的传送门。两个门永久存在、可双向传送，出门沿原方向继续；出口前方被箭头挡住时整次消除失败。程序识别并标记 `TP1->2` / `TP2->1`，检查进门前和出门后的全部飞行段，门之间的空间跳跃不参与碰撞。遇到循环传送会拒绝该动作。点选步骤时，绿色箭头表示飞行路线，灰色虚线表示传送。

当前棋盘识别 43 支普通箭头、一对门，#19、#23、#41 向上箭头会进入右上门，从左下门继续向上；#23 必须在 #19 后，#41 还需清理 #29/#31。原图及 75%/125% 缩放的完整规划、执行前校验和模拟整关执行通过，中途不抓图。当前支持一对同样式门与普通箭头，可与转弯通道、黑瞳、数字障碍联合计算；多对门的配对及特殊箭头组合尚未支持，拒绝猜测。未发送实机点击。

## 输出与命令行

默认输出到当前目录 `runs/`，每次导出独立目录。可用 `--runs` 指定目录。

```bash
.venv/bin/python app.py --analyze tests/fixtures/level2.jpg
.venv/bin/python app.py --analyze screenshot.png --crop 80 600 1060 1640
```

`--analyze` 只识别、求解、导出，不连接手机、不发送点击。识别存在问题或无法求解时退出码为 2，保留可检查的识别结果。

每个输出目录包含：

- `source.png`：原始图片副本。
- `board.json`：网格、箭头路径、点击位置及识别问题。
- `overlay.png`：编号与路径校验图。
- `solution.json` / `solution.png`：完整顺序和点击坐标（求解成功时生成）。
- `execution.jsonl`：执行事件；整关执行期间不生成逐步截图。
- 计划中的 `wait_timer` 表示等待子弹，不在普通 `clicks` 列表中。

## 算法与边界

第 266 关识别 97 支箭头、3 个黑瞳及 19/39/52/72 四个数字方块。原第 20 步 #43 后移到第 22 步；#61、#69 等门槛动作在没有更多安全动作可选时等待解锁缓冲。独立模拟设备按 1.5 秒后才完成消除计数：未留缓冲可复现过早点击，修复后 97 步没有触发尚未解锁的数字方块。此结果来自模拟，不是实机过关记录。

第 228 关补回紧贴导弹头部的粉色箭头，完整识别 141 支箭头；导弹必须等该箭头及其前置阻挡清除后发射。执行前复用导弹与邻近箭头的分区，漏掉该箭头的旧棋盘会被拒绝。原图、75%、125% 缩放通过完整规划和校验；50% 下这两个相连实例可分离，但该关其他普通箭头仍可能方向失真，完整求解会拦截。

第 246 关完整识别并规划 79 支箭头。非 45 度箭身保留真实像素折线，用有宽度的发射通道计算碰撞；普通箭头也会检查这些真实斜线。紫色 #32 的飞出角度未确认，目前取实际斜率与 45 度两种方向的阻挡并集，清障后排在第 11 步。原图、75% 与 125% 缩放通过完整规划和视觉校验；75% 时不同颜色的邻近箭头粘连，现已通过可靠头部和完整路径校验后拆分。本轮使用截图及模拟验证，未点击手机。

识别采用背景分离、连通域、三角形头部检测、Zhang–Suen 骨架化、完整箭身覆盖检查和全局网格拟合；发现斜向尾部丢失时用 Guo–Hall 重新提取，仍无法覆盖时报告识别问题。求解扫描每个箭头头部前方的所有网格，忽略自身占用，记录其他阻挡者，用拓扑排序生成完整合法顺序。

样例来自用户提供的第 2 关截图与昨晚保存的运行记录。它用于验证当前实现，不代表所有皮肤、特效、压缩图片和关卡都能准确识别。识别有解并不证明视觉还原正确，真实自动执行前需核对覆盖图。

第 206 关的暗色断缝已修复：分割后仅补回同色笔画中 1～2 像素的暗缝，并拒绝低质量的圆尾头部候选。原 #20 的头部和箭身合并后为 #19，全关识别为 59 支箭头。真实背景间隔不补齐。
